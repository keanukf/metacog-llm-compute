Layer 0 — Infrastructure + Model Selection
L0.1
Logprobs from vLLM
Blocks: TLE extraction, all calibration, model selection benchmark
vLLM must return per-token logprobs via SamplingParams(logprobs=1). Currently returning empty/null on first smoke test. Must work before any candidate model can be evaluated. Check vLLM version compatibility, test with a minimal prompt, inspect raw output. Without this, TLE is impossible and no model can be selected.
L0.2
Structured output format
Blocks: action parsing, VC parsing, model selection benchmark
Pipeline must handle action parsing and VC extraction generically across model families. System prompt constrains output ("respond with exactly one line: your move"), stop sequences cut off reasoning, post-processing strips think-tags. For models with thinking mode (Qwen3, SmolLM3), enable_thinking=False must be enforced. VC needs a separate short call or enforced two-line format.
L0.3
Local pipeline validation (M1 + LM Studio)
Needs: pipeline code ready. Zero GPU cost.
Test all 7 candidate models (quantized GGUFs) locally via LM Studio's OpenAI-compatible API. Validate: (a) logprobs returned in expected schema, (b) action parsing produces valid moves, (c) VC extraction returns 0–100 values, (d) token_entropy.py computes non-null TLE. Run 3–5 TextWorld episodes per candidate. Absolute signal values will differ from full-precision vLLM, but pipeline mechanics are identical. Also write an integration test asserting the logprobs schema; run it locally against LM Studio, then against vLLM on first cloud session. Candidates: Qwen2.5-3B-Instruct, Qwen3-4B, Qwen3-8B, Llama-3.2-3B-Instruct, Phi-4-mini-instruct, SmolLM3-3B, Gemma-3-4B-IT.
L0.4
Model selection benchmark (RunPod, ~3h GPU)
Needs: L0.1 + L0.2 resolved, L0.3 passed
Run 20 episodes per candidate model per domain at C0 via vLLM at full precision. Measure four hard criteria: (1) logprob availability (binary), (2) action parseability (>80% threshold), (3) VC parseability (>80% threshold), (4) signal discrimination (AUROC of TLE vs. step-level correctness). Task performance is NOT a selection criterion (difficulty is calibrated separately in L3.1). Output: comparison table for §4.7 (Model Selection). Only dense transformer architectures evaluated; MoE and hybrid-attention (e.g. Qwen3.5 DeltaNet) excluded to avoid routing/attention confounds on TLE interpretation.

Model selected and documented
One model chosen based on benchmark results. Selection rationale documented for §4.7: functional requirements derived from design, candidate pool, empirical comparison, winner. SLM definition operationalized in methodology: fewer than 10B parameters, single GPU (≤32 GB VRAM), dense architecture only. All subsequent work uses this model exclusively. If no candidate passes all four criteria, revisit candidate pool or adjust criteria thresholds.

Layer 2 — Signals extractable
L2.1
TLE extraction works
Needs: L0.1 (logprobs arrive) + GATE 0
With logprobs fixed and model confirmed, verify compute_tle produces non-null values, that TLE differs between easy and hard prompts, and that per-step TLE values are logged correctly in episode JSONs.
L2.2
VC extraction works
Needs: L0.2 (structured output) + GATE 0
With clean output format and model confirmed, verify parse_confidence returns values 0–100 reliably. Options: two-line format (move / confidence), separate VC call after action call, or few-shot examples. Must produce non-null VC for >80% of steps.

GATE 1
Parseability check (>80% parseable moves per domain)
Run 20 episodes per domain at C0 with the selected model. Count parseable moves / total moves. If <80% after prompt fixes → add action-space constraining. If still fails → revisit model choice (re-run L0.4 with remaining candidates). This gate must pass before any GPU budget is committed to overnight runs.

Layer 3 — Pre-experiment validation
L3.1
Difficulty calibration
Needs: L1.1 + L1.2 + GATE 1
Run Always-C0 across difficulty levels with the selected model. TextWorld: vary rooms/ingredients. ToH: vary disks (3/4) and partial starts. Target: 30–50% C0 success rate. Output: difficulty_manifest.json. Task performance is tuned here, not during model selection.
L3.2
Signal discrimination (AUROC > 0.6)
Needs: L2.1 + L2.2 + L3.1
From the difficulty calibration data, compute AUROC of TLE and VC as predictors of step-level correctness at the calibrated difficulty. This reconfirms the model selection benchmark finding (L0.4) at the final task configuration. If AUROC < 0.6 for both signals at this stage → signals don't predict correctness at the chosen difficulty → adjust difficulty or revisit model.
↓
