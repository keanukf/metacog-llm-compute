# GPU experiment prep — current state and next steps

## Current state (summary)

**Working and test-covered (no GPU):**

- **Tests 1–6:** All 21 tests pass with mocks. Structure (tokens_per_sec, latency_mean, TLE, VC, ECE, episode JSON) is validated.
- **Signals:** [src/signals/token_entropy.py](src/signals/token_entropy.py) and [src/signals/verbalized_confidence.py](src/signals/verbalized_confidence.py) are implemented and accept the formats expected from the model (list of `{logprob}` for TLE; VC parsing).
- **Agent loop:** [src/agent/base_agent.py](src/agent/base_agent.py) and [src/agent/compute_stages.py](src/agent/compute_stages.py) define the step API; C0/C1/C2 call `model.generate(prompt, logprobs=True)` and use TLE/VC. C2 is still a stub (single sample, no best-of-N vote).
- **Logging and checkpointing:** [src/utils/logging_utils.py](src/utils/logging_utils.py), [src/utils/checkpointing.py](src/utils/checkpointing.py) are implemented. Pilot writes per-episode JSON; phase scripts use `list_completed_episodes` but do not run the episode loop yet.
- **Config:** [configs/pilot.yaml](configs/pilot.yaml) and [configs/experiment_core.yaml](configs/experiment_core.yaml) define model name, inference params, pilot/phase1/phase2 dimensions. [scripts/setup_cloud.sh](scripts/setup_cloud.sh) installs vLLM, transformers, textworld, and optionally downloads the model via HuggingFace.

**Stubs / not GPU-ready:**

- **Model:** [src/utils/model_wrapper.py](src/utils/model_wrapper.py) is an abstract `ModelWrapper` + `create_wrapper()` that returns a non-functional base; no `VLLMWrapper` or `HFWrapper`. Real inference cannot run yet.
- **Pilot Test 1:** Uses the mock benchmark (unrealistic ~160k tok/s). No path to run 50 real prompts and measure tok/s, latency, VRAM.
- **Pilot Tests 4–5:** [src/environments/textworld_env.py](src/environments/textworld_env.py) is a stub (hardcoded observations); `TEXTWORLD_AVAILABLE` is set but no real game loading or TextWorld API usage.
- **Pilot Test 5:** [scripts/run_pilot.py](scripts/run_pilot.py) uses `MockModel` and stub `TextWorldEnv`; no wiring to a real wrapper or real games.
- **base_agent:** `run_episode` uses fixed `tokens += 200` and `wall_clock_time = 0.0`; real runs need actual token counts and elapsed time from the model.
- **Phase scripts:** [scripts/run_phase1.py](scripts/run_phase1.py) and [scripts/run_phase2.py](scripts/run_phase2.py) load config and checkpoint dir and print a stub message; no loop over episodes, no `run_episode`, no model or env instantiation.
- **Pilot outputs:** Blueprint expects `pilot_cost_validation.md` and `pilot_feasibility_report.md`; these are not generated by the script.

**Dependency note:** [requirements.txt](requirements.txt) and setup_cloud.sh list `vllm>=0.4.0` and `transformers`; the README and blueprint assume vLLM for inference (with HF fallback). Model download in setup_cloud uses HuggingFace (tokenizer + model); vLLM typically loads from the same HF model name.

## Recommended implementation order

Implement the following **before** buying GPU so that the first on-demand run is a real pilot with real metrics and minimal surprises.

### 1. Real model wrapper (vLLM + optional HF fallback)

**Where:** [src/utils/model_wrapper.py](src/utils/model_wrapper.py)

**What:**

- Add `VLLMWrapper(ModelWrapper)` that:
  - Takes model name and dtype from config (or constructor args).
  - Uses vLLM’s API (e.g. `LLM` or `OfflinePipeline`) to load the model and run inference.
  - Implements `generate(prompt, logprobs=False, max_tokens=256, temperature=0.3, **kwargs)` returning `(text, list[dict] | None)` where each dict has at least `"logprob"` so [token_entropy.compute_tle](src/signals/token_entropy.py) works.
- Optionally add `HFWrapper` (HuggingFace Transformers with `output_scores=True`) as fallback if vLLM is unavailable or fails.
- `create_wrapper(backend="vllm", model_name=..., dtype=...)` returns the appropriate concrete wrapper; keep the existing interface so tests and pilot can swap mock vs real by config/flag.

**Why first:** Nothing else can run real inference without this. All other GPU prep depends on it.

**Reference:** Blueprint Section V (Test 1: 100–150 tok/s; Test 2: vLLM logprobs). vLLM request API returns logprobs per token; map that to the list-of-dicts format your TLE code expects.

### 2. Pilot: real Test 1 (inference speed) and optional real model path

**Where:** [scripts/run_pilot.py](scripts/run_pilot.py), config or env

**What:**

- Add a way to choose “real” vs “mock” for the pilot (e.g. `--real` flag or `USE_REAL_MODEL=1` or config key `pilot.use_real_model`). If unset or no GPU, keep current mock behavior so local runs still work.
- When “real” is chosen and a real wrapper is available:
  - **Test 1:** Instantiate the wrapper once, run 50 prompts (e.g. simple fixed prompts or from config), measure wall time and total output token count (and per-call latency if desired). Compute `tokens_per_sec`, `latency_mean`, `latency_std`. If `torch.cuda.is_available()`, read VRAM usage and set `vram_gb`. Write these into `benchmark["test1"]` instead of the mock.
- Use the same wrapper instance for Test 5 when running in real mode (see below). Config already has `test1_inference.num_prompts: 50` and `expected_tok_per_sec_min: 80` for validation.

**Why:** This gives you real throughput and VRAM numbers on the first GPU run and validates the blueprint’s budget (e.g. ≥80 tok/s).

### 3. base_agent: real token count and wall-clock time

**Where:** [src/agent/base_agent.py](src/agent/base_agent.py) and possibly [src/agent/compute_stages.py](src/agent/compute_stages.py)

**What:**

- Today `run_episode` uses `tokens += 200` and `wall_clock_time = 0.0`. For real runs, these must reflect actual model usage and elapsed time.
- Options: (A) Step functions return an extra value (e.g. tokens used this step), and the agent sums them and tracks time; or (B) the model wrapper (or a thin wrapper around it) records tokens per call and the agent uses that. Either way, `run_episode` should accept or compute real `tokens` and `wall_clock_time` and put them in the returned dict so pilot_calibration and phase results are correct.
- Minimal change: have each compute-stage step return something like `(action, tle, vc, tokens_used)` or wrap the model so the agent can query “last call tokens” and sum; then in `run_episode` use `time.perf_counter()` for wall time and aggregate tokens.

**Why:** Pilot and phase outputs (e.g. pilot_calibration.json, phase1 JSONs) need accurate lm_calls/tokens/wall_clock_time for cost validation and analysis.

### 4. Pilot: wire real model into Test 5 (e2e)

**Where:** [scripts/run_pilot.py](scripts/run_pilot.py)

**What:**

- When running in “real” mode, build one real model wrapper from config and pass it into the Test 5 loop instead of `MockModel`. Use the same env as today (stub TextWorld) first so the only variable is the model. That validates: real generate(), logprobs → TLE, VC parsing, episode JSON structure, and logging.
- After TextWorld is real (see below), you can switch Test 5 to use real games; until then, real model + stub env is enough to be “GPU-ready” for the pilot.

**Why:** Confirms the full chain (model → steps → logging) on GPU without depending on TextWorld being ready on day one.

### 7. Phase 1 script: episode loop with real model and checkpointing

**Where:** [scripts/run_phase1.py](scripts/run_phase1.py)

**What:**

- After the pilot is running with a real model, implement the phase1 loop: for each (domain, instance, stage, run), build episode_id, skip if in `completed`, create env (stub or real TextWorld per domain), call `run_episode(env, model, stage, step_fn=..., max_steps=...)`, build the same episode dict as in the pilot, call `save_episode_checkpoint(checkpoint_dir, episode_id, data)`. ### 8. C2 best-of-N (real implementation)

**Where:** [src/agent/compute_stages.py](src/agent/compute_stages.py)

**What:**

- In `c2_step`, call `model.generate(...)` `n_samples` times (e.g. 3), then choose the final action by majority vote over the generated actions (or by a clear rule if tie). Return the winning action and TLE/VC from the winning or first sample as needed for logging. Keep the same signature so `run_episode` and the pilot do not change.

**Why:** Pilot checklist asks “Best-of-3 + Majority Vote funktioniert?”. Doing it before GPU avoids debugging C2 on the pod.
